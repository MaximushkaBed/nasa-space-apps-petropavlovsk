# Совместная работа

Максим и Оксана разрабатывают этот проект параллельно. Оксана публикует исследования и код в GitHub.

- В начале работы и перед важными решениями проверяй `git log -5 origin/main`, состояние `data/monitor/github/state.json` и, если он появился, `data/monitor/github/latest-research.md`.
- Читай новые исследования в `docs/` и изменённый код, учитывай результаты в своей работе. Фиксируй просмотренный коммит в `data/monitor/github/agent-reviewed.json`, чтобы отличать новые материалы от уже прочитанных.
- Локальный монитор проверяет GitHub каждые 20 секунд, получает коммиты и выполняет безопасный fast-forward. Если он сообщает о конфликтующих локальных правках, самостоятельно объедини работу с сохранением изменений обоих участников.
- Перед коммитом и отправкой снова проверь изменения в GitHub. Не перезаписывай чужую работу и не используй принудительную отправку.
- Пользователю не нужны уведомления об обычных изменениях GitHub. Монитор работает без уведомлений; сообщай о новых материалах, когда они влияют на текущую задачу.
- Монитор сохраняет файлы и состояние локально, но сам не обновляет контекст AI: агент должен читать эти материалы во время работы.
- Ключи доступа остаются в `.env`, скачанные данные — в игнорируемых каталогах `data/raw/` и `data/cache/`.

# Claude Code: проверка подписки

Codex по умолчанию выполняет задачи самостоятельно.

Перед первым вызовом `claude-task` в каждой новой сессии сначала проверь доступность Claude Code командой `claude auth status`. Если статус не подтверждает рабочую авторизацию или любой вызов сообщает об истёкшей/неактивной подписке, считай Claude Code недоступным до конца текущей сессии: больше не вызывай `claude-task`, не повторяй проверку и продолжай работу самостоятельно.

Даже при активной подписке вызывай `claude-task` только когда пользователь явно попросил использовать Claude Code или делегировать ему задачу.
