# Подбор условий исторического сравнения

[Цель и порядок этапов](development-goal.md) зафиксированы отдельно. Первый этап
встроен в существующие атлас и анализ территории; новый фронтенд или отдельная
система публикации не создаются.

## Путь пользователя

1. В атласе выделить круг, полигон или границу и открыть «Анализ территории».
   В анализе также доступны международные пресеты и собственный прямоугольник.
2. Выбрать вопрос: необычность периода, сравнение двух лет либо проверка
   согласования спутника относительно Aqua.
3. Нажать «Предложить условия». До выбора варианта территория и параметры
   остаются прежними. Подбор не запускает пространственный расчёт.
4. Проверить источник, историю, базу, изменения и ограничения варианта;
   явно применить условия. Ручные настройки доступны отдельно.
5. Запустить анализ. Готовый результат открывает соответствующее представление:
   календарь, сравнение лет или проверку согласования.
6. Проверка результата показывает пригодность выбранного сравнения по реальному
   сохранённому расчёту. Для аномалии она относится к выбранному месяцу.

Переключение отображаемого спутника и вопроса использует готовый расчёт, если
геометрия и научные фильтры не изменились. Изменение территории, истории,
базы, сетки, SP/NRT или времени суток требует нового расчёта. Ответ предыдущего
запроса не заменяет новое исследование. Назад/Вперёд и обычные ссылки восстанавливают
состояние без автоматического создания вычислительной задачи.

Готовый мировой обзор загружается заранее. При выборе примера СКО атлас загружает
готовый календарь и матрицу за 2022–2025 годы (норма 2022–2024, SP, сетка 10 км).
Снимок помечен датой архива. Другая территория или настройки требуют расчёта
при открытии календаря или факторов.

После пересчёта этого примера сохраните согласованную пару результатов командой
`python scripts/export_world_atlas.py --preset sko --analysis-id ID --matrix-id ID`.
Готовый снимок публикуется вместе с атласом в `web/data/sko-study.json.gz`.

## Предварительный подбор

`POST /api/v1/study-plan` принимает:

```json
{
  "question": "anomaly",
  "platform": "auto",
  "config": {
    "preset": "brazil",
    "bbox": [-61.5, -18, -50, -7],
    "start": "2020-01-01",
    "end": "2025-12-31",
    "baseline_start": 2020,
    "baseline_end": 2023,
    "grid_km": 10,
    "quality": "sp",
    "daynight": "all"
  }
}
```

Допустимые вопросы: `anomaly`, `compare-years`, `sensor-transition`.
Платформа — `auto` либо одна из платформ текущего API. Конфигурация проходит ту же
валидацию, что анализ: точные GeoJSON и круги поддерживаются, исходные фильтры
сохраняются.

Ответ содержит `version`, `requested_config`, `availability`, максимум три
`options`, `recommended_option_id` и `warnings`. У варианта есть `id`, `title`,
`description`, `platform`, фактический `config`, список `changes` с причинами,
`limitations`, статус `proposed|unavailable` и причина недоступности.
Ручной вариант сохраняет запрос; при автоматическом выборе для ручного режима
сначала требуется явно выбрать одну платформу.

Источник — опубликованный мировой календарь, либо явно подписанный сохранённый
снимок `web/data/world-calendar.json`. Ни Parquet-архив, ни внешние источники
в этом запросе не сканируются. Доступность обозначает глобальное присутствие
продукта. Полные SP-месяцы используются как консервативное предварительное
основание; точные маски дат и локальная модель проверяются после анализа.

Для вопроса аномалии подбор ориентируется на последний выбранный календарный
год. Изменение конца истории или базы присутствует в `changes`; запрос
`requested_config` остаётся неизменным. Для сравнения лет история сохраняется,
а два года выбираются в готовом представлении. Предложение перехода платформ
пока означает необходимость отложенной региональной проверки.

## Проверка готового результата

`GET /api/v1/analyses/{id}/study-assessment?question=anomaly&platform=NOAA-20&month=2025-04`
проверяет сохранённый результат, его версию метода и исходный снимок, а не
сегодняшний мировой календарь. Отсутствующий результат возвращает 404,
незавершённый или устаревший — 409. Некорректные параметры дают 400.

Ответ: `status=ready|limited|unavailable`, `title`, `summary`, `reasons`,
`limitations`, `facts`, `global_availability`, `local_coverage=unknown`.
Факты включают ID анализа/выборки, хэши конфигурации и источников, месяцы,
базовые годы и результаты проверок региональной модели.

Для аномалии проверяются точная целевая маска результата, минимум три других
года, неполные сутки UTC и нулевая база. Для перехода нужны положительный
коэффициент, все пройденные проверки модели, не менее 24 месяцев обучения
и 12 теста, а также пригодность фактических целевых SP-значений. NRT не получает
допуск из проверки стандартного архива.

`ready` означает выполнение условий выбранного сравнения в записанных данных.
Он не устанавливает локальную видимость, полноту реальных пожаров, причинность
или глобальную точность метода. Постоянный коэффициент сохраняет ранги и процент
отклонения при одинаковом пересчёте текущего значения и собственной базы.

## Проверки

`tests/test_study_plan.py` проверяет API и научные ограничения, включая реальный
сохранённый индекс доступности, SP/NRT, короткую историю, геометрию и отсутствие
скрытых задач. `tests/e2e_study_planner.py` проверяет пользовательский путь
в Chromium на явно синтетических данных; он не обращается к рабочим расчётам
и не доказывает точность гармонизации реальных пожаров.

Локальная проверка 15 ноября: полный набор Python — 83 теста без ошибок
и пропусков; браузер — 111 проверок в 11 сценариях, без ошибок JavaScript
и запросов к рабочему API. Отдельно проверен подбор условий через настоящий
локальный API на сохранённом индексе для Бразилии, Калифорнии и Канады.
Этот прогон не выполнял региональные расчёты на полном архиве.

Дополнительно проверены пять сохранённых реальных расчётов сервера: СКО,
штат Нью-Йорк, Италия, Самоа и круг радиусом 1 км. Из их суточных агрегатов
и индекса доступности точно воспроизведены месячные значения, модели,
сезонные и недельные профили. Проверены 1340 оценок условий сравнения;
непринятая модель не получила допуска, нулевая норма — процентной аномалии.
Полный архив повторно не сканировался. Это проверка воспроизводимости
и совместимости с реальными результатами, не независимая проверка пожаров.

Воспроизведение в окружении с DuckDB, расширением spatial, Playwright
и установленным Chromium:

```sh
python -m unittest discover -s tests -v
python3 tests/e2e_study_planner.py --output-dir /tmp/nasa-study-planner-check
```

Версионное сравнение результатов, независимые свидетельства, чат-помощник и MCP
остаются последующими этапами из цели разработки.
